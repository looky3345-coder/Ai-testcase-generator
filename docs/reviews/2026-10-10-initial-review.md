# 2026-10-10 초기 구조 리뷰

대상 커밋: `3a87c73` (1~2단계 구현 상태). 코드 정적 분석 기준이며 실제 LLM 호출은 하지 않았다.

## 1차 리뷰: 현재 파이프라인의 문제점 (영향 큰 순)

1. **LLM 컨텍스트 부족** — 스니펫이 미커버 라인 ±2줄(`SNIPPET_CONTEXT_LINES`)뿐이라
   해당 라인에 도달하는 조건식(경계값 분석의 근거)이 빠진다. 모델/스키마/픽스처 정보도 없다.
   → 감싸는 함수 전체 포함, 또는 대상 프로젝트를 cwd로 두고 에이전트가 직접 파일을 읽게 한다.
2. **브랜치 정보 손실** — `missing_branches`의 `[from, to]` 중 `from`만 사용해 어느 방향
   분기가 빠졌는지 프롬프트에 없다. 라인 갭과 중복 호출도 발생한다.
3. **호출 단위 과다** — 갭 339개 × 2모델 = 678회. 함수 단위로 묶으면 비용↓ 품질↑.
4. **JSON 출력 미보장** — 프롬프트 지시뿐, 파싱·검증·재시도 없음. 구조화 출력 옵션 사용 필요.
5. **교차검증 기준** — 자연어 케이스의 "일치" 판정은 부정확하다. 실행 통과 + 목표 라인 커버리지 증가를
   1차 기준으로, 모델 간 일치는 보조 신호로.
6. **CSV 경유 실행의 한계** — 순수 함수 외(FastAPI, DB 상태)는 CSV로 표현이 어렵다.
   케이스 설계 → pytest 코드 생성 → 실행 → 커버리지 측정 → 실패 피드백 루프로 3·4·5단계 통합 권장.
7. **기타** — `claude -p` 도구 권한 미제한, 타임아웃 180초, `cli.py` 미사용 import, README 경로 불일치.

## 2차 리뷰: 추가 요구사항 검토

### (1) 개발 과정 히스토리화
→ ADR 0001로 채택. `CLAUDE.md` 규칙 + `docs/HISTORY.md` + ADR + 리뷰 문서.

### (2) 무과금 로컬 모델(Ornith 등)로 대체 가능한가
**가능.** 단, 구조 변경이 필요하다. → ADR 0002 (제안)

- Ornith(9B/35B 등 오픈 웨이트)는 Ollama, llama.cpp, LM Studio, vLLM으로 구동 가능하다고 알려져 있다.
  9B Q4 양자화 기준 약 6GB로 일반 노트북(RAM 8GB+)에서도 실행 가능, 35B는 VRAM 12~24GB 필요.
  (출처가 대부분 서드파티 글이므로 공식 모델 카드로 확인 필요)
- 이 런타임들은 모두 OpenAI 호환 HTTP API를 제공하므로, 서브프로세스 CLI 대신
  **HTTP 백엔드 1개만 구현하면 모든 로컬 런타임을 지원**할 수 있다. 표준 라이브러리(`urllib`)만으로 구현 가능.
- Ollama는 JSON 스키마로 출력을 강제(grammar-constrained decoding)하는 구조화 출력을 지원 →
  로컬 모델의 약점인 형식 이탈을 상당 부분 해결.
- 감수할 점: 소형 모델은 추론력·긴 컨텍스트가 약하다. 따라서
  - 1차 리뷰 1~3번(함수 단위, 필요한 맥락만 정확히) 개선이 로컬 전환의 전제 조건이 된다.
  - "에이전트가 저장소를 탐색"하는 방식은 로컬 소형 모델로는 불안정 → 맥락 수집은 파이썬(AST)이 결정적으로 하고, 모델은 생성만.
  - 품질 판정을 실행·커버리지 기반으로 해야 소형 모델의 환각을 걸러낼 수 있다.
- 듀얼 교차검증은 이질적인 로컬 모델 2개(예: Ornith + 다른 계열)로 유지 가능.

### (3) 중간에 소형 LLM을 두고 사용자 인터랙션 구축
**가능하며 권장.** 단, 소형 모델에게 결정을 맡기지 말고 "자연어 → 구조화 명령" 변환기로 한정. → ADR 0003 (제안)

```
사용자 ⇄ [소형 LLM: 의도 해석·요약] → 명령(JSON, 스키마 검증)
                                        ↓
                  [파이썬 오케스트레이터: 갭 추출/필터/실행/커버리지 측정]  ← 결정적
                                        ↓
                  [생성 모델: 케이스 설계·테스트 코드 생성]  (로컬 대형 or 유료 선택)
                                        ↓
                  결과 요약 → 사용자 승인/수정 요청 → 반복
```

- 예시 상호작용: "attendance 라우터에서 브랜치 갭만 우선순위 높은 순으로 보여줘" →
  `{"action":"list_gaps","file_contains":"attendance","kind":"branch","sort":"priority"}`
- 승인 지점: 갭 선택 후 / 케이스 설계 후(코드 생성 전) / 생성 테스트 실행 후
- 같은 로컬 런타임(Ollama)에서 소형(예: 1~4B)·생성용(9B+) 모델을 함께 띄우면 추가 비용 없음.

## 권장 구현 순서
1. LLM 백엔드 추상화 + OpenAI 호환 HTTP 백엔드(Ollama) + 구조화 출력
2. 갭을 함수 단위로 묶고 분기 방향·함수 전체를 프롬프트에 포함
3. 응답 파싱/검증 → 테스트 코드 생성 → 실행 → 커버리지 증가 측정
4. 소형 LLM 대화 계층(REPL) + 승인 지점
