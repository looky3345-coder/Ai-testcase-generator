# 0001. 개발 히스토리 기록 정책

- 상태: 채택
- 날짜: 2026-10-10

## 배경
프로젝트 요구사항: 앞으로의 개선·개발 과정을 모두 히스토리로 남겨야 한다.
git 커밋만으로는 "왜 그렇게 결정했는지", "검토했지만 채택하지 않은 안"이 남지 않는다.

## 검토한 선택지
- A: git 커밋 메시지만 사용 — 별도 관리 비용이 없지만, 설계 맥락·기각된 안이 사라진다.
- B: README "현재 상태" 섹션 갱신 — 현재 상태만 남고 과거가 덮어써진다 (기존 방식).
- C: git 커밋 + `docs/HISTORY.md`(시간순 로그) + ADR(설계 결정) + 리뷰 문서 — 문서가 늘지만 맥락이 보존된다.

## 결정
C를 채택. 규칙은 루트 `CLAUDE.md`에 둔다 (Claude Code 세션이 자동으로 읽으므로 AI 작업에도 강제된다).
README는 사용법·현재 상태 요약만 유지하고, 과거 경위는 HISTORY로 옮긴다.

## 영향
- 모든 변경 커밋에 HISTORY 항목이 함께 들어간다.
- 추후 필요하면 CI에서 "코드 변경 시 HISTORY.md 변경 여부"를 검사하도록 확장할 수 있다.
