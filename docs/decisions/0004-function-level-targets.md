# 0004. LLM 호출 단위를 갭에서 함수로 변경

- 상태: 채택
- 날짜: 2026-10-10

## 배경
기존에는 미커버 갭(연속 라인 구간, 분기 출발 라인) 하나당 LLM을 1회 호출하고, 갭 앞뒤 ±2줄만 보여줬다.
- 실제 프로젝트 기준 갭 339개 × 모델 2개 = 678회 호출
- 갭에 도달하는 조건식이 스니펫 밖에 있어, 경계값 분석의 근거를 모델이 볼 수 없음
- 분기 갭이 `[출발, 도착]` 중 출발만 써서 어느 방향 분기가 빠졌는지 알 수 없음
- 같은 함수의 갭들이 각각 따로 호출되어 케이스 중복

## 검토한 선택지
- A: 갭 단위 유지 + 컨텍스트만 확대 — 호출 수·중복 문제는 그대로
- B: 함수 단위로 묶기 — 호출 수 감소, 함수 전체 흐름 제공. 긴 함수는 프롬프트가 길어짐
- C: 파일 단위로 묶기 — 호출 수 최소지만 로컬 소형 모델의 컨텍스트 한계를 쉽게 넘음

## 결정
B. `TestTarget` = 함수 하나(데코레이터 포함) + 그 안의 갭 전체.
- 함수가 `MAX_FUNCTION_LINES`(120)보다 길면 헤더(데코레이터+시그니처) + 갭 주변(±8줄)만
- 함수 밖(모듈 레벨) 갭은 파일별로 한 대상, 갭 주변(±5줄)만, 다른 함수 본문으로 넘어가지 않게 자름
- 분기 갭은 `(출발, 도착)` 쌍 단위로 만들고, 출발 라인이 아예 미실행인 분기는 라인 갭과 중복이므로 버림
- 같은 이름 함수(property getter/setter 등)를 구분하기 위해 이름이 아닌 AST 노드 기준으로 묶음

## 영향
- 출력 `gaps.json` → `targets.json`, 프롬프트/응답 파일명이 `<gap_id>` → `<target_id>` (호환성 깨짐)
- `--limit`은 갭 수가 아니라 대상 함수 수 상한
- 로컬 소형 모델 사용 시에도 함수 하나 분량이면 컨텍스트 한계 내 (ADR 0002와 정합)
